## JimPowerMizer v0.1.5

### New: energy savings
JimPowerMizer now records how long each graphics profile is applied and, from power figures you enter,
works out how much energy that saved. The game can't measure power, so the figures come from you.

- **Setup:** `/jpm` → **Savings** tab. Enter your PC's power draw in watts with your own graphics
  settings, and with each graphics profile applied. A plug-in power meter at the wall gives the best
  figures. Graphics card software (e.g. HWiNFO, `nvidia-smi`) only measures the card, so use the same
  method for every figure, with the game in the foreground.
- **How it's worked out:** energy saved = time applied × (watts at your settings − watts with the
  profile). Watts entered later count for time already recorded. A profile drawing as much as your own
  settings, or more, shows no saving.
- **Optional:** a price per kWh with a currency symbol, and grams of CO2 per kWh (from your supplier or
  your country's average). Each part only appears once its figure is entered; nothing is shown for
  figures you leave empty.
- **`/jpm stats`:** time, energy, cost and CO2 per profile, plus lifetime and this-session totals.
  `/jpm stats reset yes` clears the stats and keeps your figures.
- **In chat:** with "Chat message when switching" on, the message when a profile ends adds what it
  saved, e.g. `Restored your graphics settings (situation ended). Max saver: 20 min, ~50 Wh saved
  (~£0.01, ~10 g CO2)`. Only for profiles with watts entered; otherwise the message is unchanged.
- **Storage:** account-wide (`JimPowerMizerDB.global.savings`), keyed by profile name. Renaming a
  profile keeps its stats and watts. Deleting one moves its time and energy to a "Deleted profiles"
  total, and a new profile with the same name starts from zero.
- **Known limit:** there's no window-focus API, so time with the game in the background counts the same
  as in the foreground. While the game's background frame rate cap (`maxFPSBk`) is in force, e.g. when
  alt-tabbed, the savings shown may be too high.

### Changes
- **Hide names and nameplates** also turns off friendly player nameplates
  (`nameplateShowFriendlyPlayers`), and puts your setting back when the profile ends.

### Fixes
- **Settings the game changes together:** some CVars set others when written. For example, the minion
  names CVar also sets the pet, guardian and totem name CVars. The resulting `CVAR_UPDATE` events were
  taken for changes you made, so those CVars lost their saved values and weren't restored when the
  profile ended. Changes the game makes during the addon's own writes are no longer counted as yours,
  and a CVar changed by a later write in the same switch is set again.
